# Neovim Config

Personal Neovim config (v0.12+) that emulates VSCode editing behavior. Lua-only, no plugin framework.

## Layout

- `init.lua` — entry point: `vim.loader.enable()`, requires `config.options`, `config.vscode`, then each `plugins.*` module, plus the global `<C-q>` quit map
- `lua/config/options.lua` — `vim.opt` settings grouped by comment headers
- `lua/config/vscode.lua` — the core: always-insert emulation, Select-mode selection, clipboard, pane switching
- `lua/plugins/*.lua` — one file per plugin: `vim.pack.add` + `setup()` + keymaps
- `nvim-pack-lock.json` — pinned plugin revs, auto-generated by `vim.pack`

## Plugins: vim.pack, NOT lazy.nvim

Neovim 0.12's built-in `vim.pack` manages plugins. Sources live in `~/.local/share/nvim/site/pack/core/opt/`.

```lua
vim.pack.add({ "https://github.com/owner/repo" })  -- table form REQUIRED
```

- A bare string argument silently does nothing — always pass a table.
- Repo name ≠ module name. Check before `require`: `project.nvim` → `project_nvim`, `smear-cursor.nvim` → `smear_cursor`, `nvim-autopairs` → `nvim-autopairs`.
- First `require` after adding a plugin races the async clone. Verify on a second launch, or pre-fetch with `nvim --headless -c 'lua vim.pack.update()' -c 'qa!'`.
- Adding a plugin = new `lua/plugins/<name>.lua` + one `require("plugins.<name>")` line in `init.lua`.
- `nvim-pack-lock.json` is rewritten by vim.pack whenever a session syncs specs. A long-running nvim started before a plugin removal will resurrect the deleted entry on its next sync — restart nvim after plugin changes, and expect occasional lockfile churn in `git status`.
- snacks.nvim dashboard's `startup` section hard-requires lazy.nvim — do not re-add it (we replaced it with `recent_files`).

## VSCode emulation invariants (config/vscode.lua)

The whole file is gated by `is_editable_buffer(buf)`: `buftype == ""`, name is not a directory, filetype not `minifiles*`. All editing maps are installed **buffer-locally** by `setup_buffer_maps(buf)` on `BufWinEnter`; UI buffers (nvim-tree, telescope, help, terminal) keep native keys.

- Always-insert: editable buffers auto-enter Insert on `BufWinEnter`, except blank `[No Name]` scratch buffers (`is_blank_scratch`) which stay Normal.
- Insert `<Esc>` re-enters Insert via `vim.on_key` + `vim.schedule` — a bare `vim.cmd.startinsert()` inside autocmds is silently dropped in unsafe contexts (cmdline exit, plugin mappings). Same reason all `feedkeys` calls go through `vim.schedule` with `"nx"` mode.
- `<C-w>` closes the *buffer* on editable buffers (accepted tradeoff: shadows Vim's window prefix). On non-editable buffers it's remapped to `wincmd p` (or `<C-c>` for prompt buftypes); terminal keeps native `<C-w>`.
- `<C-q>` (init.lua) = `:confirm qa` — quits everything, prompts to save. Global, all modes.
- Normal-mode Ctrl+arrows pane-switch ONLY while NvimTree is visible; otherwise they fall back to word motion.
- Select-mode is emulated (`ensure_select`, `select_from_insert`, `collapse_select`, `page_goto`) so Shift+arrows extend selections like VSCode. Do not "simplify" these into plain `v` mappings — the Select↔Visual auto-switch and caret-column compensation are load-bearing.

## Hard-won gotchas

- `vim.fn.isdirectory()` returns `0`/`1`, and **`0` is truthy in Lua**. Always compare `== 1`. This bug once stripped every editable-buffer map.
- `vim.schedule` is required around `startinsert`/`feedkeys` inside autocmds and mappings.
- `vim.bo[buf].filetype` on `NvimTree` buffers is `NvimTree`; directory buffers opened via `nvim .` have empty buftype/filetype — the isdirectory check is what excludes them.
- No which-key/leader-key convention — maps are direct VSCode chords: `<C-p>` files, `<C-S-f>` grep, `<C-S-p>` telescope meta-picker, `<C-b>` tree, `<C-s>` save, `<C-g>` goto line, `<C-f>` find, `<C-z>`/`<C-y>` undo/redo, `` <C-`> `` terminal, `<C-w>` close buffer.

## Colorschemes

`lua/plugins/colorscheme.lua`: tokyonight is default (`:colorscheme tokyonight` → moon variant). catppuccin, kanagawa, rose-pine stay installed for `:Telescope colorscheme` live previews. Variants: `tokyonight-storm/-day/-night`, `catppuccin-mocha/-latte/-frappe/-macchiato`, etc.

## Verifying changes

No test suite. Verify live:

- Headless probes: `nvim --headless -c 'lua print(...)' -c 'qa!'` (check `vim.bo`, `nvim_get_mode()`, `maparg`)
- Real sessions in `/tmp` test dirs; drive them with `nvim --headless --cmd` or a terminal multiplexer
- After ANY vscode.lua or plugin change, restart nvim and exercise: file open (should land Insert), `<C-w>` close, `<C-q>` quit, nvim-tree toggle, Shift+arrow selection

## Conventions

- Match existing style: 2-space indent, double quotes, `--` comment headers atop each file explaining purpose + the vim.pack/lockfile note on plugin files
- Commit style: short imperative subject ("Add <C-q> to quit all windows with save confirmation", "Exclude directory buffers from the editable check"), body only when the why isn't obvious
- Keep `init.lua` requires alphabetical-ish by concern; global one-off maps go at the bottom with a comment
